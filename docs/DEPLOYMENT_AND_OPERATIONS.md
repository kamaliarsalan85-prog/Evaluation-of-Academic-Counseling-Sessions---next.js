# راهنمای استقرار، پایگاه داده، پشتیبان‌گیری و راه‌اندازی سامانه ارزیابی جلسات مشاوره

## ۱. بررسی راهبردهای میزبانی (Hosting & Deployment Strategy)

با توجه به اینکه در حال حاضر دامنه، سرور و پایگاه داده آماده ندارید، سه گزینه اصلی از نظر دسترسی در ایران، محدودیت‌های پرداخت ارزی، پایداری و سادگی نگهداری ارزیابی شده‌اند:

### گزینه A: Google Cloud Run + Cloud SQL for PostgreSQL
- **مزایا:** مقیاس‌پذیری خودکار، SSL آماده، بکاپ‌گیری خودکار Cloud SQL، مدیریت بدون سرور (Serverless).
- **محدودیت‌های حیاتی برای کاربران در ایران:**
  - دسترسی پنل Google Cloud و ثبت‌نام حساب Billing نیازمند کارت بانکی بین‌المللی، احراز هویت غیرتحریمی و دسترسی بدون محدودیت منطقه‌ای است.
  - احتمال اختلال یا مسدودیت دسترسی از داخل ایران به سرویس‌های Google Cloud در سطح IP یا Billing وجود دارد.
- **جمع‌بندی:** اگر دسترسی پایدار به حساب و کارت بین‌المللی ندارید، گزینه مناسبی برای راه‌اندازی مستقیم نیست.

### گزینه B: سرور مجازی (VPS) داخل ایران یا خارج + Docker + PostgreSQL
- **مزایا:**
  - **قابل پرداخت با کارت شتاب (ریالی)** از ارائه‌دهندگان معتبر داخلی (مانند ابر آروان، پارس‌پک، ایران‌سرور و ...) یا پلتفرم‌های PaaS ایرانی (مانند لیارا / فندق / چابکان).
  - بدون ریسک مسدودیت حساب یا تحریم کارت بانکی.
  - دسترسی سریع و کم‌تاخیر برای دانش‌آموزان و مشاوران داخل ایران.
  - پشتیبانی کامل از گواهینامه SSL رایگان (Let's Encrypt / Caddy / Nginx) و دامنه `.ir` یا `.com`.
- **نیازمندی سخت‌افزاری پیشنهادی:** حداقل ۱ تا ۲ هسته CPU، ۲ گیگابایت RAM، ۲۰ گیگابایت SSD (برای Next.js + PostgreSQL 16).

### گزینه C (پیشنهادی برای سادگی عملیاتی): سرویس PaaS با پشتیبانی از Docker و PostgreSQL مدیریت‌شده
- پلتفرم‌هایی که استقرار مبتنی بر `Dockerfile` و دیتابیس **Managed PostgreSQL** ارائه می‌دهند (چه در داخل ایران مانند سرویس‌های ابری بومی، چه در خارج مانند Railway / Render / Fly.io در صورت داشتن دسترسی پرداخت)، کمترین هزینه نگهداری را دارند زیرا SSL، بکاپ خودکار دیتابیس و راه‌اندازی مجدد سرویس را خودشان انجام می‌دهند.

## ۲. متغیرهای محیطی مورد نیاز (`.env`)

یک فایل `.env` از روی `.env.example` بسازید و مقادیر زیر را تنظیم کنید:

- `DATABASE_URL`: آدرس اتصال استاندارد PostgreSQL برای Prisma Client.
- `DIRECT_URL`: آدرس اتصال مستقیم PostgreSQL برای اجرای Migrationها (در صورت استفاده از Connection Pooler مانند PgBouncer، آدرس مستقیم را قرار دهید؛ در غیر این صورت برابر `DATABASE_URL`).
- `AUTH_SECRET`: رشته تصادفی حداقل ۶۴ کاراکتری برای امنیت نشست‌ها (تولید با `openssl rand -hex 32`).
- `ADMIN_BOOTSTRAP_SECRET`: (توصیه‌شده در محیط تولید) کد یک‌بارمصرف امنیتی برای ایجاد نخستین Super Admin در مسیر `/admin/setup`.
- `APP_URL`: دامنه نهایی سامانه (مثال: `https://eval.example.ir`).
- `NODE_ENV`: در سرور نهایی حتماً `production` تنظیم شود.

## ۳. دستورات راه‌اندازی و Migration پایگاه داده

۱. نصب وابستگی‌ها:
```bash
npm ci
```

۲. تولید Prisma Client و اجرای Migrationها روی PostgreSQL:
```bash
npx prisma generate
npx prisma migrate deploy
```

۳. (اختیاری) درج داده‌های اولیه فرم استاندارد و تنظیمات:
```bash
npm run db:seed
```

۴. ساخت نسخه تولید (Production Build) و اجرا:
```bash
npm run build
npm run start
```

۵. بررسی سلامت سرویس (Health Check):
- مسیر `GET /api/health` وضعیت اتصال واقعی به PostgreSQL را برمی‌گرداند (`200 OK` با `database: "connected"`).

## ۴. راه‌اندازی نخستین مدیر ارشد (Initial Super Admin)

- هیچ رمز عبور پیش‌فرضی در کد قرار داده نشده است.
- پس از نخستین استقرار، مقدار `ADMIN_BOOTSTRAP_SECRET` را در محیط سرور تنظیم کنید.
- به نشانی `/admin/setup` بروید، نام کامل، نام کاربری، رمز عبور قوی و کد `ADMIN_BOOTSTRAP_SECRET` را وارد کنید.
- به‌محض ایجاد نخستین حساب `SUPER_ADMIN`، مسیر ثبت‌نام عمومی به‌صورت دائمی در پایگاه داده قفل می‌شود.

## ۵. پشتیبان‌گیری و بازیابی اطلاعات (Backup & Disaster Recovery)

### برنامه پیشنهادی پشتیبان‌گیری:
- **روزانه (خودکار در ساعت ۳ بامداد به وقت تهران):** تهیه بکاپ کامل فشرده با نگهداری حداقل ۱۴ نسخه اخیر.
- **هفتگی:** نگهداری یک نسخه در فضای ذخیره‌سازی مجزا (Object Storage / S3 یا سرور دوم).
- **پیش از هر Migration یا ارتقاء:** بکاپ دستی فوری.

### دستور تهیه پشتیبان (`pg_dump`):
```bash
pg_dump "$DATABASE_URL" --format=custom --no-owner --no-privileges -f "backup_$(date +%Y%m%d_%H%M%S).dump"
```

### دستور بازیابی (`pg_restore`):
```bash
pg_restore --clean --if-exists --no-owner --no-privileges -d "$DATABASE_URL" backup_20261123_030000.dump
```

### تایید سلامت بکاپ:
- ماهی یک‌بار یک فایل `.dump` را روی یک دیتابیس آزمایشی بازیابی کرده و تعداد رکوردهای جدول‌های `submissions` و `submission_answers` و اجرای موفق `SELECT COUNT(*) FROM submissions;` را بررسی کنید.
